# 03a · 聊天列表（窗口 · 群聊）

路由 `#/chat`。底栏中间的「聊天」、首页目录 I 都会进来。点一行进聊天页 `#/chat/t?id=对话id`（见 `03-聊天.md`）。

网址参数：`?new=1`（打开新建）、`?archived=1`（看归档）。

预览图：`previews/03a-chatlist.png`（列表）、`03a-chatlist-swipe.png`（左滑操作）、`03a-chatlist-new.png`（新建）、`03a-group.png`（群聊）、`03a-group-choose.png`（群里让谁来回）。

代码：`src/pages/ChatList.jsx` + `src/components/chat/chatlist.css`；群聊和单聊共用 `src/pages/Chat.jsx`。

## 页面上有什么

| 区块 | 说明 |
|---|---|
| 窗口 | 和他的每一个对话。每行：头像、名字、来自哪个窗口（主窗口 / 窗口 2…）、最后一句（他在回时显示「回复中…」）、时间、没看的数量。置顶的有火漆 |
| 接入一个新窗口 | 虚线卡片，**预留**：以后多接一条 Codex，就能多开一种窗口 |
| 群聊 | 头像叠在一起、几个人、最后一句带说话人 |
| 左滑 | 置顶 / 归档 / 删除（电脑上右键）。已归档的在最下面「已归档 N 个」里，可以放回去 |
| 新建 | 新窗口：起名字 + 接到哪个窗口；新群聊：起名字 + 还拉谁进来（他默认在） |
| 群聊页 | 和单聊一样，多了：消息上面写是谁说的；顶部是成员；按「回复」时选「大家 / 只要某某」 |

## 后端要准备什么（建议）

失联时统一返回 `available: false`。字段的准确名字以 `src/lib/mock.js` 为准。

| 做什么 | 接口 | 说明 |
|---|---|---|
| 列表 | `GET /api/chats` | 三组：窗口、群聊、已归档。每个：id、类型（window / group）、名字、来自哪个窗口、成员（id、名字、头像、颜色）、置顶没、最后一句的预览、最后时间、没看的数量、在不在回 |
| 接入有哪些 | `GET /api/connections` | 每条：id、名字、类型（window = 他的窗口 / member = 可以拉进群的成员）、一句说明 |
| 新建 | `POST /api/chats` | 窗口：名字 + 接到哪条；群聊：名字 + 成员。返回新对话的 id |
| 置顶 / 归档 / 改名 | `PATCH /api/chats/{id}` | |
| 删除 | `DELETE /api/chats/{id}` | 连同聊天记录 |

聊天页的接口都换成 `/api/chats/{id}/…`（发消息、回复、暂停等，见 `03-聊天.md`）。群聊的「让他回」可以带「让谁回」（成员 id），不带就是大家。

## 怎么接 Codex（建议）

### 几个概念

| 前端看到的 | 后端里是什么 |
|---|---|
| 一条「接入」（主窗口、窗口 2…） | 一套 Codex 配置：调用方式、模型、**工作目录**（他的人设文件、记忆文件放在这里，Codex 会读目录里的 AGENTS.md）、权限（沙箱）、密钥。密钥只放后端，前端永远拿不到 |
| 一个「窗口」（Ash · 日常） | 一个 Codex 会话（thread）。第一次聊时开一个，把会话 id 存在这个对话上；之后每次都接着这个会话（resume），他就记得前面聊过什么 |
| 「和日常共用记忆」 | 几个窗口指向同一个工作目录：会话各是各的，但人设和记忆文件是同一份 |
| 群聊里的成员 | 每个成员一条接入、一个会话 |

### 两种接法，任选

1. **后端直接跑 Codex**（推荐，最贴近他平时的样子）：后端所在的机器装好 Codex，用它的非交互模式或官方 SDK 来跑，一次「回复」就是在这个会话上跑一轮，并把过程中的事件一条条读出来。适合他本来就是一个跑在电脑 / 服务器上的 Codex。
2. **调 OpenAI 的接口**：后端用 Codex 系列模型、走流式接口；工具调用由后端自己执行。适合只想要对话、不需要他真的在机器上动手的情况。

具体的命令、参数和事件名，以 Codex 当时的官方文档为准。

### 事件怎么变成聊天里的消息

| Codex 那边 | 聊天里 |
|---|---|
| 开始这一轮 | 推「状态：在回」 |
| 推理 / 思考摘要 | 下一条消息上的「想了一下」 |
| 执行命令（命令、输出、退出码、用时） | 一条「命令行」消息；输出很长时截到 2000 字以内 |
| 改了文件、查了网页等其他动作 | 也可以做成「命令行」消息，标题写清楚做了什么 |
| 回复的文字 | 文字消息（可以边写边推，同一个 id 覆盖） |
| 这一轮结束 | 推「状态：null」 |
| 出错 / 超时 | 把正在写的那条标成「失败」，保留写了一半的字 |

**每收到一个事件，就更新一次「最后一次动静」的时间**，前端靠它判断「仍在等待」（30 秒）和「卡住了」（2 分钟）。命令跑得久的时候，也要隔一会儿推一次动静，不然会被误判成卡住。

### 她发的东西怎么交给 Codex

- **文字**：多条「待回复」按时间拼成这一轮的输入，引用的那句放在前面（例如「（回复你说的：……）」）。
- **图片**：Codex 能看图，把图片文件一起传进去。
- **语音**：后端先转成文字再交给他；文字也存在消息上，前端「转文字」会用到。
- **文件**：存进他的工作目录，在输入里告诉他文件名，让他自己去读。
- **表情**：转成一句描述交给他，比如「[表情：抱着爱心的猫]」。

### 暂停、重新生成

- **暂停**：结束正在跑的这一轮（停掉进程或取消请求），已经推出去的文字保留。
- **重新生成**：删掉他这条，在同一个会话里用同样的输入再跑一轮。

### 群聊怎么编排

- 「让谁回」选**大家**时：后端按顺序让成员一个个回，后一个人的输入里带上前面人刚说的话（「Nori：……」）。
- 选**某一位**时，只跑那一位。
- **每次「回复」每个成员最多说一轮**，不要让他们互相接话停不下来。
- 群聊的会话和他单聊的窗口分开，免得群里的话混进单聊的上下文；需要的话可以在群聊的会话里给他一句提示，比如「这是你们三个人的群」。

### 安全

- 沙箱只给他的工作目录，不给整台机器；能不联网就不联网。
- 命令输出推给前端之前，过滤掉密钥、令牌、密码之类。
- 一个窗口同时只跑一轮；新的「回复」要等上一轮结束或暂停。

### 「接入一个新窗口」（预留）

以后在「设置 · 接入」里加一条接入：名字、调用方式、工作目录、模型、权限。加好后 `GET /api/connections` 会多一条，新建窗口时就能选它。前端不需要改。
